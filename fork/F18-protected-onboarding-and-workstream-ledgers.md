# F18 Protected Onboarding And Workstream Ledgers

Date: 2026-08-03
Status: active

## Intent

Keep fork-first onboarding, agent safety constraints, public provenance limits, and implementation evidence durable across upstream reconciliations.

## Required Behavior

- README presents the fork identity and safety warning before executable commands.
- README links the current run guide and patch guide.
- Agent instructions prohibit cloning without user authorization for the exact source and destination.
- Agent onboarding uses least privilege and reviews scripts before dependency installation or execution.
- Communal alignment is described as procedural coordination without moral authority, universal consensus, or inherent safety claims.
- Project intent does not replace code review or claim a complete safety audit.
- Public provenance states only narrow claims supported by linked public records.
- Public docs never disclose or infer contributor topology, collaborator access, human identity, account relationships, private services, or personal information.
- README, RUN, patch guide, active feature specs, governance, active workstream ledgers, and repository-local delivery skills survive upstream reconciliations as protected fork material.
- Protection is described as repository policy and does not imply a GitHub branch setting.
- Each complex fork workstream keeps a top-level `.ledger` record with objective, scope, decisions, review, gates, commit state, risks, and closeout.
- Ledgers link the repository-local workflow skill that governed delivery when that skill is tracked.
- Ledgers use neutral public-safe evidence and never store credentials, private topology, local absolute paths, or personal data.

## Upstream Reconciliation Rule

- Preserve governance, onboarding, active feature contracts, repository-local skills, and ledgers required by active workstreams during every upstream reconciliation.
- Historical ledgers may remain as labeled evidence but create no current preservation, reconciliation, release, or verification obligation.
- Override upstream documentation changes that weaken clone authorization, privacy, publication, or exact-origin policy.
