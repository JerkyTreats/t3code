# Autonomous run

A long run drives one fixed predicate, not a duration or a stream of plausible work.

1. State the goal, checkable finish predicate, scope, resource budget and existing action grants before the first iteration.
2. Create a decision trail and choose the actual T3 wake mechanism from the adapter when work must wait beyond the active turn.
3. Make one justified unit of progress, verify it, keep or discard the attempt, and record the evidence and predicate result.
4. Address reversible blockers within scope and route unrelated discoveries to a backlog; keep the original predicate as the main drive.
5. Continue while supported progress and the authorized budget remain, pivoting on evidence rather than relaxing the finish condition.
6. Stop at the verified predicate, explicit pause or stop, stated resource limit or a documented dead end; retire any task-owned watch or schedule when the run ends.

Keep going within an active turn without manufacturing a timer. A persistent scheduler is an explicit operation and consumes future provider work; use only the granted cadence and budget. A wakeup rechecks whether the run is still active before dispatching new work. Report retained and discarded attempts and the exact final predicate state.
