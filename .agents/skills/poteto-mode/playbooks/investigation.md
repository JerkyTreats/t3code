# Investigation

The deliverable is a cited answer or recommendation. Keep the project read-only.

1. Restate the question and locate the affected subsystem, its entry points, state and external boundaries.
2. Follow the real data flow and inspect independent evidence. For motivation, inspect history and decision records as well as current code.
3. Test an observable hypothesis with a bounded read-only probe when it changes the answer. Preserve the user's no-edit constraint.
4. Explain the mechanism, key concepts, source locations and gotchas, or compare alternatives with a recommendation and tradeoffs.
5. Review the answer for unsupported claims and provide citations to the evidence actually read.

The throughput checkpoint is one line, `n/a: read-only investigation`. An answer that reveals a possible change does not start Feature automatically. Incomplete evidence limits the conclusion.
