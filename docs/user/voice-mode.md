# Voice Mode

Turn on **Voice** in the composer to ask for conversational replies that are easy to listen to. After a reply finishes, your device reads it aloud using your environment's voice service. The spoken words are the same as the text reply, not a separate summary.

Voice mode is off by default and saved on this device. It applies to new messages you send, including queued messages. Opening a thread does not read its history, and another connected device does not start speaking your replies.

Queued replies only start speaking while you stay in their thread. A new task queued offline keeps the conversational response style but does not start audio later when you reopen it.

Use **Stop audio** to stop listening and **Replay reply** to hear the latest spoken reply again. Turning voice off or leaving the thread clears playback. On mobile, starting dictation stops speech first. Voice output does not add dictation support to devices that do not already have it.

If your browser blocks automatic audio, select **Replay reply**. If speech is unavailable, the text reply still appears normally. Your environment operator must configure a local voice service before playback can work. Long replies can exceed its limit and remain text-only.

Replies begin playing after speech generation completes. This is turn-by-turn listening, not an always-listening conversation. Voice mode asks the agent to use natural spoken language but does not remove technical details you explicitly request.
